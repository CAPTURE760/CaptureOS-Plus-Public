## 提交信息风格：详细型

### 格式

```
type(scope): 一句话概括（≤50字）

## 改动详情
- 模块1: 具体改动点，说明为什么改、怎么改的
- 模块2: 具体改动点，说明为什么改、怎么改的

## 影响范围
- 受影响的页面/功能/接口

## 验证方式
- 如何验证这些改动有效
```

### type 取值
- feat: 新功能
- fix: 修复 bug
- refactor: 重构（不改功能）
- docs: 文档
- style: 格式调整
- test: 测试
- chore: 构建/工具/杂项

### 规则
1. **scope 必填**，如 backend/frontend/api/db/backup/search/ui
2. **改动详情至少 3 条**，每条说明：
   - 改了什么文件/模块
   - 为什么改（问题/需求）
   - 怎么改的（关键实现方式）
3. **影响范围要具体**，不要只写"前端页面"，要写"搜索页/导出按钮/列表页"
4. **验证方式要可操作**，如"访问 /search 切换时间筛选后返回，关键词应保留"
5. 中文描述，技术术语可保留英文
6. 不带 Co-Authored-By 尾注
